What is HeltarChat? HeltarChat is a service that sends and receives WhatsApp messages for businesses. Instead of typing every message by hand, a business can connect its own software to HeltarChat.

What is "your software"? It could be an online shop, a clinic's booking system, or a spreadsheet that holds customer details. Anything that can make a request to a web service.

What is an API? An API is a set of rules that lets two programs talk to each other. It works like a restaurant menu: you choose what you want, the kitchen makes it, and it comes back to you. You never need to see the kitchen.

Example: An online shop wants to message a customer when their order ships. The shop's software asks HeltarChat to send the message. That request is the whole idea of this course.

Each module has a short explanation, simple steps, and practice items. Start with the Glossary if you come across unfamiliar words.

Glossary: words you'll see

Come back here any time a word is unfamiliar.

API
Rules that let one program ask another program to do something, like a menu for software.
API key
A secret code that identifies your software. Treat it like a password.
Read-only key
A key that can look up information but cannot send messages or change anything.
Request
A message your software sends to HeltarChat asking for something, such as "send this text."
Webhook
A notification HeltarChat sends to your software when something happens. Like a doorbell: you don't have to keep checking the door.
Contact
A saved person in HeltarChat, usually identified by their phone number.
Template
A business message that WhatsApp has approved in advance. Business messages to customers usually need one.
Campaign
One message sent to a list of people at the same time.
Status update
A report on something you sent, such as "delivered" or "read".
Pagination
Long lists are split into pages. You get one page, then ask for the next.
Security code (HMAC)
A code made from your secret key that proves a request really came from you. It must be made on a server, because anything in a web browser can be seen by others.
Domain
Your web address, such as yourshop.com.
DNS
The phone book of the internet. It connects a web address to the place it lives.

Module 1: Permission keys Complete

What this is about

Before your software can send anything, HeltarChat needs to know it's allowed to. The API key is that permission.

An everyday comparison

A hotel gives each guest a key card for their own room. Your software gets an API key to open HeltarChat's door. Anyone who holds the card can get in, so keep it private.

Why you'd need it

Example: A clothing shop wants an automatic message when an order ships. Its software must show a valid key with every request. Without the key, HeltarChat ignores the request.

How a request works

What you do

  1. Log in to your HeltarChat account on the website.
  2. Look for a section named Developers, API, or Integrations. The name may differ slightly.
  3. Create a new key and name it something clear, such as "My test key".
  4. Choose Read-only. This is the safe choice while you learn.
  5. Copy the key and save it in a password manager or other private place.

What you should see

A long string of random letters and numbers. You can usually see the full key only once, so copy it before you close the page.

If something goes wrong

If you can't find the developer section, your account may not have that access yet. Ask whoever set up your HeltarChat account, or contact HeltarChat support.

Module 2: Contacts and messages Complete

What this is about

Most of your daily work is saving people as contacts and sending them messages. You save the contact first, because HeltarChat needs to know who a person is before it can message them.

An everyday comparison

Saving a contact is like adding someone to your phone's address book. If the name already exists, you update it instead of creating a duplicate. HeltarChat calls this an upsert: "add if new, update if it exists."

Sending a message

A message can be plain text, or it can include a file such as a photo or PDF. To send a file, your software first uploads it, then refers to it in the message. It's like attaching a file to an email, done in two steps.

Reading the results

Example: You send a message to three customers. HeltarChat replies with two lists: success and fail. Each item is numbered by its place in your original list. Item 1 is your first customer, item 2 is your second, and so on. That's how you know who received it.

Long lists

If you have thousands of contacts, HeltarChat returns them in pages. Each page comes with a bookmark (a cursor) that points to the next page. Keep asking for the next page until no bookmark comes back.

What you do

  1. Write the customer's phone number with the country code, such as +91 for India.
  2. Save the contact with their name and any details you want to keep.
  3. Save the same contact again with one detail changed.
  4. Open the contact in your HeltarChat dashboard to confirm the change appeared.

What you should see

The contact appears once, not twice, and shows the updated detail.

If something goes wrong

If a number is rejected, check that it has the country code and no typing errors. A number without a country code is the most common cause.

Module 3: Sending to many people Complete

What this is about

A campaign sends one message to a list of people. For business messages, WhatsApp requires a template that has been approved in advance.

An everyday comparison

A template is like a printed letter that has been checked by head office before branches can use it. You can fill in the customer's name, but you can't change the wording without a new approval.

Templates

Every template has a category, such as marketing or utility (order updates, for example). It also has a status. Only approved templates can be sent. If a template is still waiting for approval, it won't send.

Small list or large list

  • Small list: put the recipients directly in your request.
  • Large list: put them in a file with one person per line. You can prepare this in a spreadsheet and save it as a text file.

Checking how it went

  • The campaign summary shows the overall result.
  • The per-person status shows what happened to each recipient.

Scheduling

You can set a campaign to send on a future date, up to two years ahead. Double-check the time zone, because a message scheduled for the wrong time is easy to do by accident.

What you do

  1. Choose an approved template and note its category.
  2. Prepare your recipient list with country codes.
  3. Send now, or schedule the campaign for later.
  4. Check the summary, then look at the per-person results.

Module 4: Getting automatic updates Complete

What this is about

Instead of repeatedly asking HeltarChat "anything new?", you give it an address on your system. When something happens, HeltarChat sends the news to that address. This address is called a webhook.

An everyday comparison

A webhook works like a doorbell. You don't keep checking the front door all day. You get on with your work, and the bell tells you when someone arrives.

Two kinds of news

  • A new message: a customer wrote to you.
  • A status update: something you sent was delivered or read.

Your software should check which kind it received before handling it.

How a webhook arrives

Two rules

Confirm quickly. Your system should send back a "got it" reply within 10 seconds. If it takes longer, HeltarChat assumes it failed and may send the news again.

Failures add up. If your system keeps failing, HeltarChat stops sending to it after about 100 failures in a row. You'll need to fix the problem and switch the webhook back on.

What you do

  1. Give your technical contact a web address that can receive news. They will set this up.
  2. Enter that address in the webhook settings in HeltarChat.
  3. Send yourself a test message.
  4. Check that the news arrived and that the "got it" reply was sent.

Module 5: Practical tasks Complete

What this is about

These are three common tasks that come up once you're live: adding your own information to contacts, receiving files from customers, and using your own website address for tracked links.

Adding your own information

You can attach your own details, such as an order number, to a contact. It's like adding extra boxes to a form. Your technical contact can set this up using a feature called metaCustomFieldHook.

Receiving files from customers

Example: A customer sends you a photo of a damaged product. HeltarChat gives every message a unique ID, called a WAMID. Your software uses that ID to fetch the message and its photo.

Using your own web address for links

Links you send can show your own website address, such as links.yourshop.com, instead of a generic one. This builds trust with customers.

What you do: set up a link address

  1. In HeltarChat, open the link settings and add the address you want to use.
  2. HeltarChat shows you a short verification record. Copy it.
  3. Log in to the company that manages your domain, and find its DNS settings (the place where web addresses are set up).
  4. Create the record exactly as HeltarChat shows it.
  5. If you use Cloudflare, set the record to DNS only (grey cloud, not orange). Otherwise verification fails.
  6. Return to HeltarChat and click verify.

If something goes wrong

Verification can take a while after you add a record. If it still fails after an hour or so, check that the record matches exactly and that it's set to DNS only.

Module 6: Connecting other tools Complete

What this is about

An integration connects HeltarChat to a tool you already use, so information moves between them automatically instead of being copied by hand.

An everyday comparison

It's like a power adapter. Two devices can each work on their own, but the adapter lets them share a power supply without rewiring either one.

Marketing tools

  • WebEngage, CleverTap, and MoEngage are marketing tools. Each one can receive message status updates from HeltarChat, so your marketing reports stay accurate.

Chat on your website or app

Example: A visitor to your website opens a chat box and talks to your team. The chat box connects to HeltarChat behind the scenes. A security code is needed so only your website can use it. That code must be created on your server, not in the visitor's browser, so it stays secret.

Storing data in the cloud

Amazon S3 is online file storage. You can export your HeltarChat data there for backup or analysis.

What you do: connect a tool

  1. Open the integrations area in HeltarChat.
  2. Choose the tool you use and follow its connection steps.
  3. Send a test and check that it appears in that tool.

Quick quiz

Try to answer from memory, then open each answer to check.

1. What is an API key, in one sentence?

It's a secret code that proves your software has permission to use HeltarChat.

2. Why doesn't a successful send mean the customer has read the message?

A successful send means HeltarChat accepted it. Delivery and reading happen afterwards, and you find out through status updates.

3. How do you know if a message is from a customer or a status update?

A customer message is news that someone wrote to you. A status update reports on something you sent, such as delivered or read.

4. Why must the security code be made on a server?

If it were made in a web browser, anyone could see it and misuse your access.

5. Why must the verification record be set to DNS only?

Cloudflare's proxy hides the real record, so HeltarChat can't see it and verification fails.
