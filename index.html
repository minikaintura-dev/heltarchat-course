What is HeltarChat? HeltarChat sends and receives WhatsApp messages for businesses. This course teaches you how your own software can talk to HeltarChat, so messages, contacts, and campaigns can happen automatically.

What is an API? An API (Application Programming Interface) is a set of rules that lets one program ask another program to do something. Think of it like a restaurant menu: you pick an item, the kitchen prepares it, and you get it back. You never need to see the kitchen.

What do I need? A HeltarChat account, access to its dashboard, and a basic idea of how to copy and paste text. Some modules involve a developer; the notes say so when that applies.

Start with the Glossary if terms feel unfamiliar, then work through the modules in order.

Glossary: words you'll see

Come back here any time a term is unfamiliar.

API
A set of rules that lets one program request actions or information from another.
API key
A long secret code that identifies your software to HeltarChat. Treat it like a password: never share it or put it in a public web page.
Bearer token
The way you attach your API key to a request. It's sent in a header line that begins with the word Authorization.
Endpoint
A specific web address for one action, such as sending a message. Example: https://api.heltar.com/v1 plus a path.
Scope
A permission attached to an API key. A read-only key can look things up but cannot change anything.
Payload
The data inside a request or message: the recipient, the text, and so on.
JSON
A common format for structured data, written as labels and values in curly braces. Most API data uses it.
Webhook
A notification HeltarChat sends to your software when something happens, such as a new incoming message. It's like a doorbell instead of you checking the door every few seconds.
WAMID
A unique ID WhatsApp gives each message. You use it to look up a specific message later.
Template
A pre-approved message format used for business campaigns. WhatsApp requires approval before a template can be sent.
Campaign
A message sent to a list of people, usually as a single batch.
Message vs. status
A message is something a customer said to you. A status is an update on something you sent, such as "delivered" or "read".
HMAC
A fingerprint made from your secret key and some data. It proves a request really came from you. It must be created on a server, because a browser would expose your secret.
CNAME
A DNS record that points one domain name to another. Used here to verify that you own a domain.
DNS only
A setting on a DNS record that stops a service such as Cloudflare from hiding the real record. Verification fails if it's turned off.
Pagination
Splitting a long list into pages. You request one page, then use a cursor (a bookmark) to get the next.

Module 1: Foundations and Authentication Complete

What this module is about

Before your software can do anything, HeltarChat needs to know who is asking. The API key is your software's ID card. Every request you make must show it.

The address you'll use

All requests start with the same base address: https://api.heltar.com/v1. Each action adds a path to the end of it.

Responses come in a standard wrapper

Every answer from HeltarChat is wrapped in a standard package, called an envelope. Look at the status first (did it work?), then at the data inside.

Rate limits: don't send too much too fast

HeltarChat limits how many requests you can make in a short time. If you go over, you'll get an error. The fix is to wait briefly, then try again.

How a request works

Step by step: create an API key

  1. Log in to the HeltarChat dashboard.
  2. Open the developer or API settings area.
  3. Choose Create API key.
  4. Give it a clear name, such as "Test key".
  5. Pick a preset. Read-only is safest while learning. Full access lets the key make changes too.
  6. Copy the key immediately and store it somewhere safe. You may not be able to see it again.

Step by step: use the key in a request

  1. Add a header to your request named Authorization.
  2. Set its value to the word Bearer, a space, and your key.
  3. Example: Authorization: Bearer your-key-here

Module 2: Messaging and Contacts API Complete

What this module is about

This is the everyday work: saving people as contacts, and sending them messages. Contacts come first, because you can't message someone who isn't saved.

Message types

A message can be plain text or include media such as an image or PDF. For media, you first upload the file, then refer to it in your message. Think of it as attaching a file to an email, but in two steps.

Reading the send result

When you send to several people, the reply is split into two lists: success and fail. Each entry is numbered by its position in your original list. So the first recipient you sent to is position 1 in the reply. Match by position to know who got it.

Contacts

  • Upsert means "create if new, update if it exists". You never need to check first.
  • Attributes are extra details you store on a contact, such as city or plan type.
  • Pagination lets you read a large contact list in chunks. Use the cursor from each page to get the next one, and stop when no cursor comes back.

Step by step: save a contact

  1. Prepare the phone number with the country code, such as +91....
  2. Send an upsert request with the number and any attributes.
  3. Send the same request again with one attribute changed.
  4. Check the contact in the dashboard to confirm the change.

Module 3: Campaigns, Templates and Scheduling Complete

What this module is about

A campaign sends one message to many people. For business messages, WhatsApp requires a pre-approved template, so campaigns always start with choosing the right template.

Templates

Each template has a category (for example, marketing or utility) and a status. Only approved templates can be used. If a template is still pending, it won't send.

Sending to a list

For a small list, put the recipients in your request. For a large list, use the NDJSON format, which is a file with one recipient per line. It's easy to create in a spreadsheet and export as a text file.

Checking on a campaign

  • The get one request shows the campaign as a whole.
  • The per-recipient status request shows what happened to each person.

Scheduling

You can schedule a campaign for a future date, up to two years ahead. Check the time zone carefully, because scheduled times are easy to get wrong.

Step by step: plan a small campaign

  1. Pick an approved template and note its category.
  2. List your recipients with their country codes.
  3. Send the campaign, or schedule it for later.
  4. Check the campaign status, then the per-recipient results.

Module 4: Webhooks and Real-Time Events Complete

What this module is about

Instead of asking HeltarChat "any new messages?" over and over, you give it an address (a webhook URL). When something happens, HeltarChat sends the news to you straight away.

Two kinds of notifications

  • messages[] means a customer sent you something.
  • statuses[] means an update on something you sent, such as delivered or read.

Check which one is present before you process a notification, so you handle each correctly.

Rules to follow

Reply quickly. Your endpoint must answer with HTTP 200 within 10 seconds. If it takes longer, do the heavy work afterwards.

Retries. If your endpoint fails, HeltarChat retries up to 5 times.

Disabling. After about 100 failures in a row, the webhook is switched off. You'll need to fix it and turn it back on.

How a webhook arrives

Step by step: test your webhook

  1. Set up a web address that can receive notifications.
  2. Register that address in the HeltarChat webhook settings.
  3. Send yourself a test message.
  4. Confirm your endpoint logs the notification and returns 200.

Module 5: Guides in Practice Complete

What this module is about

These guides cover real tasks you're likely to need: storing your own information on contacts, receiving files customers send, and using your own domain for tracked links.

Storing your own data

The metaCustomFieldHook lets you pass your own fields, such as an order number, into HeltarChat. Think of it as adding extra boxes to a form.

Receiving media from customers

When a customer sends a photo or document, the notification tells you its WAMID (a unique message ID). Use GET /v1/messages?wamid= with that ID to fetch the message and its file.

Custom link domain

Tracked links can use your own domain instead of a generic one. You add the domain, then create a verification record (a CNAME) in your domain's DNS settings. That record must be set to DNS only, or verification will fail.

Step by step: add a link-tracking domain

  1. Open the link tracker settings in HeltarChat and add your domain.
  2. Copy the verification record HeltarChat shows you.
  3. In your domain provider's DNS settings, create that record.
  4. If you use Cloudflare, set the record to DNS only (the grey cloud, not the orange one).
  5. Return to HeltarChat and click verify.

Module 6: Integrations Complete

What this module is about

An integration connects HeltarChat to a tool you already use, so data flows between them without copying it by hand.

Marketing platforms

  • WebEngage: syncs message status through webEngageStatus.
  • CleverTap: uses cleverTapStatus for status and cleverTapMessages for messages.
  • MoEngage: connects through the moEngage integration.

Chat on your website or app

You can add a chat widget to your website, or embed agent chat in your own app. For the widget, a security code (HMAC) must be created on your server. If it were created in the browser, anyone could see your secret.

Exporting data to Amazon S3

S3 is online file storage. An export sends your HeltarChat data there, for analysis or backup.

Step by step: connect a marketing platform

  1. Open the integrations area in HeltarChat.
  2. Choose your platform and follow its connection steps.
  3. Send a test event and confirm it appears on the platform side.

Final Assessment

Try to answer each question from memory, then open the answer to check.

1. Why doesn't a 200 response to a send request guarantee the message was delivered?

A 200 means HeltarChat accepted the request. Delivery happens afterwards, so track it with status webhooks or the per-recipient status request.

2. What happens after about 100 consecutive webhook failures?

The webhook is switched off. Fix the endpoint and turn the webhook back on.

3. How do you tell a customer message from a status update?

Customer messages arrive in messages[]. Delivery updates arrive in statuses[].

4. Why must the web widget security code (HMAC) be created on the server?

If it were created in the browser, your secret would be visible to anyone who views the page.

5. Why must the verification CNAME be set to DNS only?

A proxied record hides the real value, so verification can't read it and fails.
