    <h2>Module 1: Foundations and Authentication <span class="done-badge">Complete</span></h2>

    <div class="goal"><strong>Goal:</strong> Make your first authenticated API call.</div>


    <h3>Core concepts</h3>

    <ul>

      <li>Base URL: <code>https://api.heltar.com/v1</code></li>

      <li>Every success returns <code>message</code> and <code>data</code>. Errors return <code>errorType</code>, <code>errorMessage</code>, <code>errorsValidation</code>, <code>errorRaw</code>.</li>

      <li>Phone numbers use international format without <code>+</code>, for example <code>919876543210</code>.</li>

      <li>Rate limits: list reads 600 per 15 min, analytics 60 per 15 min, key management 20 per 15 min. Sends are not limited this way.</li>

    </ul>


    <h3>Authentication</h3>

    <ul>

      <li>Create a key under <strong>Settings → API Key / Dev tools</strong>. The full key is shown only once.</li>

      <li>Send it as <code>Authorization: Bearer hk_live_…</code></li>

      <li>Scopes are <code>resource:action</code>, such as <code>messages:write</code>. A call outside the key's scope returns <code>403</code>.</li>

      <li>Presets: <strong>Full access</strong> and <strong>Read-only</strong>.</li>

    </ul>


    <pre><code>curl -X GET "https://api.heltar.com/v1/clients?limit=5" \

  -H "Authorization: Bearer hk_live_xxxxxxxx"</code></pre>


    <div class="exercise">

      <strong>Practice exercises</strong>

      <label><input type="checkbox" data-ex="1-1"> Create a read-only key.</label>

      <label><input type="checkbox" data-ex="1-2"> Call <code>GET /v1/clients?limit=5</code> and confirm a 200 response.</label>

      <label><input type="checkbox" data-ex="1-3"> Call <code>POST /v1/messages/send</code> with that key and confirm you get <code>403</code>.</label>

    </div>

  <section class="module" id="m2" data-module="2">

    <h2>Module 2: Messaging and Contacts API <span class="done-badge">Complete</span></h2>

    <div class="goal"><strong>Goal:</strong> Send every message type and manage contacts programmatically.</div>


    <h3>Sending messages</h3>

    <ul>

      <li>Supported <code>messageType</code> values: <code>text</code>, <code>media</code>, <code>template</code>, <code>interactive</code>, <code>contacts</code>, <code>location</code>, <code>reaction</code>.</li>

      <li>Templates are required outside the 24-hour customer service window. Variables map to <code>{{1}}</code>, <code>{{2}}</code> by position.</li>

      <li>Read <code>data.success</code> and <code>data.fail</code> carefully. Both are keyed by array position, so match results back to what you sent.</li>

      <li>Use <code>refId</code> to correlate your own IDs.</li>

    </ul>


    <h3>Media workflow</h3>

    <ol>

      <li><code>GET /v1/messages/presigned-url?file_name=…&amp;file_type=…</code></li>

      <li><code>PUT</code> the file to <code>signedRequest</code> (expires after one hour).</li>

      <li>Send the message with the returned <code>url</code>.</li>

    </ol>


    <h3>Contacts</h3>

    <ul>

      <li><code>POST /v1/clients</code> creates or upserts in bulk. Attributes merge key by key.</li>

      <li>Attribute types: <code>text</code>, <code>numerical</code>, <code>dropdown</code>, <code>tags</code>. Define non-text types first with <code>POST /v1/business/attributes</code>.</li>

      <li>Pagination is keyset-based: pass <code>nextCursor</code> back as <code>cursor</code> until it is <code>null</code>.</li>

    </ul>


    <div class="exercise">

      <strong>Practice exercises</strong>

      <label><input type="checkbox" data-ex="2-3"> Print the successes and failures from the response.</label>

    </div>

  <section class="module" id="m3" data-module="3">

    <h2>Module 3: Campaigns, Templates and Scheduling <span class="done-badge">Complete</span></h2>

    <div class="goal"><strong>Goal:</strong> Run bulk campaigns reliably and manage the template lifecycle.</div>


    <h3>Templates</h3>

    <ul>

      <li>Categories: <code>UTILITY</code>, <code>MARKETING</code>, <code>AUTHENTICATION</code>. Components must include <code>BODY</code>.</li>

      <li>Statuses: <code>PENDING</code>, <code>APPROVED</code>, <code>REJECTED</code>, <code>PAUSED</code>, <code>DISABLED</code>.</li>

      <li>Editing replaces the whole component list, and approved templates go back to review.</li>

      <li>Pause all marketing sends with <code>PUT /v1/business/pause-marketing-templates</code>.</li>

    </ul>


    <h3>Campaigns</h3>

    <ul>

      <li>Small batches go in <code>messages</code>. Large ones use an NDJSON file, one recipient per line, referenced by <code>finalPayloadFileUrl</code> with <code>recipientCount</code>.</li>

      <li>Track counts with <code>GET /v1/campaigns/get-one/:id</code>. Per-recipient status is at <code>GET /v1/campaigns/:id</code>.</li>

    </ul>


    <h3>Scheduling</h3>

    <ul>

      <li>Schedule a message, campaign or nudge with a Unix timestamp no more than two years ahead.</li>

      <li>Scheduling a nudge cancels pending nudges for the same contact and bot.</li>

    </ul>

      <label><input type="checkbox" data-ex="3-2"> Schedule a campaign 10 minutes ahead to two test numbers.</label>

  <section class="module" id="m4" data-module="4">

    <h2>Module 4: Webhooks and Real-Time Events <span class="done-badge">Complete</span></h2>

    <div class="goal"><strong>Goal:</strong> Receive and process events reliably.</div>


    <h3>Setup</h3>

    <ul>

      <li>Configure URLs with <code>POST /v1/business/webhook-url</code>. Each URL subscribes to one field type.</li>

      <li>Use <code>headers</code> to send a static shared secret, since there is no signature header.</li>

    </ul>


    <h3>Payload discrimination</h3>

    <table>

      <tr><th>Event</th><th>Where it arrives</th></tr>

      <tr><td>Inbound customer message</td><td><code>value.messages[]</code></td></tr>

      <tr><td>Status change (sent, delivered, read, failed)</td><td><code>value.statuses[]</code></td></tr>

      <tr><td>Payment</td><td>Status with <code>"type": "payment"</code></td></tr>

      <tr><td>Call event</td><td><code>"field": "calls"</code></td></tr>

    </table>


    <h3>Reliability rules</h3>

    <ul>

      <li>Respond <code>200</code> within 10 seconds. Process asynchronously.</li>

      <li>Only network errors, timeouts and <code>5xx</code> are retried, up to 5 times over roughly 4 to 5 hours. Sort by payload timestamps, not arrival time.</li>

      <li>Deduplicate on <code>(wamid, status)</code>.</li>

      <li>After about 100 consecutive failures the webhook is disabled. Re-enable it with the configure endpoint.</li>

    </ul>

    <h2>Module 5: Guides in Practice <span class="done-badge">Complete</span></h2>

    <div class="goal"><strong>Goal:</strong> Apply the three guides to real workflows.</div>


    <h3>Custom data in webhooks</h3>

    <ul>

      <li>Attach <code>integrations: [{ name: "metaCustomFieldHook", customField: {...} }]</code> to a template send.</li>

      <li>The returned <code>customField</code> lets you map every receipt back to your own order ID.</li>

    </ul>


    <h3>Receiving media</h3>

    <ul>

      <li>Inbound media arrives as an ID. Fetch <code>GET /v1/messages?wamid=…</code>.</li>

      <li><code>awsLink</code> may be empty for a few seconds. Retry about three times at five-second intervals.</li>

    </ul>


    <h3>Custom domain for link tracker</h3>

    <ul>

      <li>Use an unused subdomain such as <code>links.yourbrand.com</code>. Never the root domain.</li>

      <li>Add the verification CNAME exactly as sent. Don't duplicate your domain in the Name field.</li>

      <li>Set Cloudflare records to DNS only. Keep the verification record forever, because renewal depends on it.</li>

    </ul>

    <h2>Module 6: Integrations <span class="done-badge">Complete</span></h2>

    <div class="goal"><strong>Goal:</strong> Connect third-party platforms and know which webhook field each uses.</div>


    <table>

      <tr><th>Integration</th><th>What it does</th><th>Key webhook field</th></tr>

      <tr><td>WebEngage</td><td>Journeys send WhatsApp; status returns</td><td><code>webEngageStatus</code></td></tr>

      <tr><td>CleverTap</td><td>Campaigns send WhatsApp; templates import</td><td><code>cleverTapStatus</code>, <code>cleverTapMessages</code></td></tr>

      <tr><td>MoEngage</td><td>Campaigns, journeys and replies</td><td><code>moEngage</code></td></tr>

      <tr><td>Web chat widget</td><td>In-page chat in the same inbox</td><td>Inbox (no webhook)</td></tr>

      <tr><td>Embedded agent chat</td><td>Agents chat with a lead inside your CRM</td><td>None</td></tr>

      <tr><td>Amazon S3 export</td><td>CSV of status changes every 10 minutes</td><td>None</td></tr>

    </table>


    <h3>Key concepts</h3>

    <ul>

      <li>The embed <code>embedUrl</code> is single-use and expires after 24 hours. Never put the API key in the browser.</li>

      <li>Web widget identity verification signs <code>visitor.id</code> on your server with HMAC-SHA256.</li>

      <li>For S3, treat the table as append-only and keep the row with the newest <code>updated_at</code> per <code>message_id</code>.</li>

    </ul>

  <section class="module quiz" id="quiz">

    <h2>Final Assessment</h2>

    <p>Try each question first, then open the answer.</p>


    <details>

      <summary>1. Why does a 200 response to <code>POST /v1/messages/send</code> not guarantee delivery?</summary>

      <p>The 200 means the message was accepted. Delivery is reported later through <code>sent</code>, <code>delivered</code>, <code>read</code> and <code>failed</code> status webhooks.</p>

    </details>

    <details>

      <summary>2. What happens after roughly 100 consecutive failed webhook deliveries?</summary>

      <p>The webhook is disabled automatically and you are notified. Re-enable it with the configure endpoint once your endpoint is healthy.</p>

    </details>

    <details>

      <summary>3. Which field tells you whether a webhook payload is a customer message or a status update?</summary>

      <p>Look at which array is present: <code>value.messages[]</code> for inbound customer messages, <code>value.statuses[]</code> for status updates.</p>

    </details>

    <details>

      <summary>4. Why must the web widget signature be computed on the server?</summary>

      <p>The HMAC secret must stay private. If it is computed in the browser, anyone can read it and forge signatures for any visitor id.</p>

    </details>

    <details>

      <summary>5. Why must the Cloudflare verification record be DNS only?</summary>

      <p>A proxied (orange cloud) record hides the real value, which blocks both certificate verification and the final link setup.</p>

    </details>

  const modules = document.querySelectorAll('section.module[data-module]');

  const checkboxes = document.querySelectorAll('input[data-ex]');

  const STORAGE_KEY = 'heltarchat-course-progress';

    let completed = 0;

      sec.classList.toggle('done', allDone);

    document.getElementById('progressText').textContent =

  }

    cb.addEventListener('change', () => {

      const state = loadState();

      state[cb.dataset.ex] = cb.checked;

      saveState(state);

      render();

    });

  });
