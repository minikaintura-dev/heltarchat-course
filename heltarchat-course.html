Module 1: Foundations and Authentication

Complete

Base URL and envelope

All endpoints live under https://api.heltar.com/v1. Responses use a common envelope, so check the status and the data field before reading results.

Rate limits

Requests are rate limited. When you exceed the limit, back off and retry rather than sending requests in a tight loop.

Authentication

  • Create an API key in the dashboard.
  • Send it as a Bearer token: Authorization: Bearer <your-key>.
  • Choose scopes deliberately. The Full access preset grants everything; the Read-only preset only allows reads.

Module 2: Messaging and Contacts API

Complete

Message types

Messages can be text or media. For media, upload the file first using a presigned URL, then reference it in the send request.

Send responses

Send responses contain success and fail arrays. Each entry is keyed by its position in your request, so match results back to recipients by index.

Contacts

  • Use upsert to create or update a contact in one call.
  • Attach custom attributes to contacts for segmentation and personalization.
  • List contacts with keyset pagination, passing the cursor from each page to the next.

Module 3: Campaigns, Templates and Scheduling

Complete

Templates

Templates have a category and a status. Only approved templates can be used in campaigns, so check the status before sending.

Campaign sends

For small audiences, send the recipient list in the request body. For large files, use the NDJSON form, which streams one recipient per line.

Tracking a campaign

  • Use the get-one endpoint to see a campaign's overall state.
  • Use the per-recipient status endpoint to find out what happened to each recipient.

Scheduling

You can schedule a campaign up to two years in advance.

Module 4: Webhooks and Real-Time Events

Complete

Payloads

Webhook payloads contain either a messages[] array (incoming customer messages) or a statuses[] array (delivery updates). Check which one is present before processing.

Reliability rules

  • Respond with HTTP 200 within 10 seconds. Do heavy work after responding.
  • Failed deliveries are retried up to 5 times.
  • After about 100 consecutive failures, the webhook is disabled.

Module 5: Guides in Practice

Complete

Custom data with metaCustomFieldHook

Use the metaCustomFieldHook to pass your own fields through to HeltarChat.

Receiving media

When a customer sends media, look up the message by its WAMID with GET /v1/messages?wamid= to retrieve the file.

Custom link tracker domain

To track links on your own domain, add the domain, then create the verification CNAME. Set that CNAME record to DNS only, not proxied, or verification will fail.

Module 6: Integrations

Complete

Marketing platforms

  • WebEngage: use the webEngageStatus integration to sync message status.
  • CleverTap: use cleverTapStatus for status and cleverTapMessages for messages.
  • MoEngage: connect through the moEngage integration.

Chat surfaces

  • Add the web chat widget to a site. The widget's HMAC must be computed on your server, never in the browser, so your secret stays private.
  • Embed the agent chat in your own app.

Data export

Export data to Amazon S3 for analysis or archiving.

Final Assessment

Answer these from memory, then check the module notes above.

1. Why does a 200 response to a send request not guarantee delivery?

A 200 means the request was accepted. Delivery happens afterwards, so track it through the status webhooks or the per-recipient status endpoint.

2. What happens after about 100 consecutive webhook failures?

The webhook is disabled, so you need to fix the endpoint and re-enable it.

3. How do you tell a customer message from a status update?

Customer messages arrive in messages[]. Delivery updates arrive in statuses[].

4. Why must the web widget HMAC be computed on the server?

Computing it in the browser would expose your secret key to anyone who views the page.

5. Why must the Cloudflare verification CNAME be DNS only?

A proxied record makes Cloudflare return its own address instead of your DNS value, so verification fails.
